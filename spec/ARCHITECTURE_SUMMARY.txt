================================================================================
KEY CONCEPTS
================================================================================

BINARY GOVERNANCE MODEL:
  B_layout = 1  ⟺  strides are canonical (contiguous)
  B_layout = 0  ⟺  strides are non-canonical (sparse/strided)
  B_own = 1     ⟺  this view exclusively owns buffer (refcount = 1)
  B_own = 0     ⟺  buffer is shared (refcount > 1)

STATE SPACE:
  State 00: SHARED_NON_CANONICAL
  State 01: SHARED_CANONICAL
  State 10: EXCLUSIVE_NON_CANONICAL
  State 11: EXCLUSIVE_CANONICAL (creation state)

8 OPERATIONS:
  OP-1: ALLOC          → allocate tensor, B_layout=1, B_own=1
  OP-2: FREE           → destructor, Arc::drop, dealloc if refcount→0
  OP-3: VIEW           → zero-copy slice, B_own→0, refcount++
  OP-4: TRANSPOSE      → logical permutation, metadata-only
  OP-5: RESHAPE        → safe shape change (contiguous/exclusive only)
  OP-6: MATERIALIZE    → COW-based restoration to canonical exclusive
  OP-7: GET            → element read, no state change
  OP-8: SET            → element write, COW if shared

TEMPORAL SAFETY:
  Arc::strong_count ensures lifetime(view) ⊆ lifetime(buffer)
  No view can outlive its buffer
  COW isolation prevents materialization interference

================================================================================
FAIL-CLOSED DESIGN
================================================================================

All operations implement fail-closed semantics:
  IF precondition_fails:
    tensor_state remains unchanged
    error returned
  ELSE:
    operation executes atomically
    postconditions guaranteed

Examples:
  - VIEW with invalid ranges: returns error, tensor unchanged
  - SET on mismatched coordinate: returns error, no mutation
  - MATERIALIZE on invalid state: returns error or executes fully

CRITICAL INVARIANTS
================================================================================

Inv-1: Governance Correctness
  B_layout = 1 ⟺ ∀i: strides[i] = ∏_{j>i} shape[j]
  B_own = 1 ⟺ Arc::strong_count(data) = 1

Inv-2: Shape-Stride Consistency
  shape.len() = strides.len() ∧ shape.len() > 0

Inv-3: Offset Bounds
  offset < data.len() ∨ (len() = 0)

Inv-4: Refcount Positivity
  Arc::strong_count(data) ≥ 1 for all live views

Inv-5: View Containment
  For all coord in shape: physical_addr(coord) < data.len()

Inv-6: COW Isolation
  Materialization of view A doesn't affect sibling buffers

Inv-7: Temporal Safety
  lifetime(view) ⊆ lifetime(buffer) via Arc::strong_count > 0

================================================================================
INDEX MAPPING FORMULA
================================================================================

Core address generation (no framework overhead):

For logical coordinate X = (x₀, x₁, ..., x_{d-1}):
  physical_address(X) = offset + Σᵢ (xᵢ * strideᵢ)

Canonical strides for shape (s₀, s₁, ..., s_{d-1}):
  σᵢ = ∏_{j>i} sⱼ

Examples:
  Shape [2, 3]       → Canonical [3, 1]
  Shape [2, 3, 4]    → Canonical [12, 4, 1]
  Shape [5]          → Canonical [1]

Time complexity: O(d) where d = rank
Space complexity: O(1) (only local variables)

================================================================================
GENERATION COUNTER PROTOCOL
================================================================================

Generation(u64) tracks buffer identity:

ALLOC:           generation = 0
VIEW(parent):    generation' = generation  (inherited)
TRANSPOSE:       generation' = generation  (metadata only)
MATERIALIZE:     generation' = generation + 1  (new buffer)
SET (COW):       generation' = generation + 1  (new buffer)
SET (exclusive): generation' = generation  (in-place)
GET:             generation' = generation  (read-only)

Staleness check:
  if (view.generation < parent.generation):
    return Err("StaleFork")

This detects: view created before parent materialized

================================================================================
COPY-ON-WRITE ISOLATION
================================================================================

COW semantics guarantee no interference between materialized views:

Before MATERIALIZE(view_A):
  view_A.data = Arc_orig
  view_B.data = Arc_orig
  parent.data = Arc_orig
  refcount(Arc_orig) = 3

MATERIALIZE(view_A) executes:
  1. Allocate Arc_new = Arc::new(copy_of_viewed_elements)
  2. Assign view_A.data = Arc_new
  3. Decrement Arc_orig refcount: 3 → 2

After MATERIALIZE:
  view_A.data = Arc_new (exclusive, refcount = 1)
  view_B.data = Arc_orig (shared, refcount = 2)
  parent.data = Arc_orig (shared, refcount = 2)

Result: Modifications to view_A never affect view_B or parent

TENSORDESCRIP C-FFI LAYOUT
================================================================================

TensorDescriptor (76 bytes, 8-byte aligned):

Offset   Size   Field               Type              Purpose
0        8      data_ptr            *const f32        buffer start
8        8      data_len            u64               buffer element count
16       8      shape_ptr           *const u64        logical dimensions
24       8      shape_len           u64               rank
32       8      strides_ptr         *const u64        step sizes
40       8      strides_len         u64               rank
48       8      offset              u64               logical offset
56       1      is_contiguous       u8                B_layout
57       1      owns_storage        u8                B_own
58       2      _padding            u16               alignment
60       8      generation          u64               staleness check
68       8      refcount_snapshot   u64               debug info

Enables:
  - C interop (Pascal can call Rust)
  - Zero-copy buffer sharing
  - Refcount inspection
  - Staleness detection
